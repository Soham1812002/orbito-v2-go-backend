# Packet flow review and reliability plan

Reviewed: 2026-11-11. Scope: current working changes and the gateway, parsers, spool, ingestion transactions, assignment/state policies, outbox, realtime delivery, browser log page, Compose limits, logging and verification harness. This is a review and implementation plan; application behavior was not changed during this review.

## Decision

Keep the existing Go gateway -> internal HTTP -> Express -> PostgreSQL/outbox -> realtime -> browser architecture. Keep one Compose file, explicit protocol profiles, parameterized SQL and the current feature modules. No Kafka, Redis, ORM migration, generic pipeline framework or new device commands are needed.

The flow already has useful durability boundaries, but it is not yet verified against packet loss under faults or sustained load. Fix the confirmed receive-loop issue first, then add a real wire-to-database harness before optimizing concurrency.

## Current flow and guarantees

1. TCP 5001 selects Markon; TCP 5002 selects Concox. A bounded connection slot is acquired. New connections must supply an accepted login, then pass the backend registry/profile check. IMEI is an identifier, not cryptographic authentication.
2. The session buffers TCP bytes, extracts frames and validates/decodes the selected profile. Unsupported complete packets from registered sessions are diagnostics rather than invented telemetry.
3. The gateway writes normalized data and bounded raw bytes to the spool: temporary file, file sync, rename, directory sync. Only then does it send a documented application ACK. Some packet types deliberately have no application ACK.
4. One forwarder retries the same persisted event ID over authenticated HTTP. It removes the spool record only after the backend confirms that ID as persisted. Certain permanent HTTP failures move it to quarantine, not the database.
5. One database transaction performs admission, deduplication, temporal vehicle assignment, log/point writes, monotonic latest-state updates and outbox insertion. HTTP persistence success follows commit.
6. The outbox retries a notification to realtime. Realtime authorizes sockets and sends log identifiers. The browser fetches saved rows using REST; reconnection reloads the newest page. Notification acceptance is not proof that a browser received it.
7. Raw payloads expire after 7 days, device logs after 30 days and GPS points after 90 days under the current retention job. Operational JSON logs rotate independently and can drop records under pressure. Neither the browser nor operational logs are a permanent packet ledger.

**Reliability target:** every complete frame admitted from a registered session must have an explicit, reconcilable outcome: pending durable record, committed receipt/log, duplicate of a committed record, or retained quarantine record. Malformed, unauthorized, capacity-rejected and incomplete traffic must be counted separately. Preserve documented ACK-after-durability behavior.

An unconditional promise that no device packet can ever be missed is impossible: bytes may never reach the host, the tracker may not retry, some types have no application ACK, and host-disk destruction loses a local spool. TCP transport ACKs acknowledge kernel receipt, not database persistence. Prove zero unexplained loss within a documented workload/failure envelope; record exclusions and recovery limits.

## Packet conversion validation

Use the supplied PDFs and captured bytes as the oracle, not an encoder and decoder that share the same bug. Current reference: `V5_UPDATED.pdf` (physical page numbers) and `.docs/PROTOCOL_TRANSPORT_REVIEW.md`.

| Packet/profile | Current verified conversion | Further proof required |
| --- | --- | --- |
| Concox login `0x01` | BCD identifier, serial, CRC and exact ACK covered by PDF fixture tests. Model code remains a manufacturer value; `8066` is not a verified public model mapping. | Real standard/EG02 login captures; invalid BCD, profile mismatch, duplicate/replacement connection and registry failure. |
| Standard heartbeat `0x13` | Captured `78780a130406040002013d98e50d0a`: battery 6, GSM 4, ignition false, charging true, tracking false; no position. Exact same-serial ACK is tested. | All documented status bits/levels and tail values, reconnect/retransmission and extended layouts. No remote GPS-enable inference from bit6. |
| EG02/EG03 heartbeat `0x23` | External voltage is a big-endian two-byte value /100, not categorical battery level. PDF fixture covers 39.86V. | Minimum/maximum values and correct profile rejection; hardware capture. |
| Location `0x22` | Big-endian coordinates /1,800,000; hemisphere/course flags, km/h speed, fix/history status and optional raw mileage. One PDF location fixture is tested; no invented ACK. | All hemispheres, heading boundary, zero speed, invalid fix, optional layouts, serial wrap, stale/future timestamps and real model location capture. PostGIS must store POINT(longitude latitude), REST/UI must preserve canonical fields. |
| Alarm `0x26` | Decoder exists for constrained 32/36-byte layouts with conditional ACK policy; alarm code preserved. | Golden tests for supported language/layout combinations and every decoded offset/flag/ACK. Ambiguous language zero and other packet variants remain diagnostics. Do not claim complete alarm support today. |
| Information `0x94/00` | PDF pp.26/31: subtype plus two voltage bytes /100, no location/device timestamp and no server response. Tests cover zero, 11.83V, max voltage, wrong layouts and CRC failure. | Replay a captured complete frame through the TCP-to-DB harness, confirming no ACK and no overwrite of ignition/position. |
| Other Concox types/subtypes | Unsupported diagnostics, not location. | Enable only against exact model/layout/CRC/ACK evidence; no speculative `0x12`, `0x19`, `0x27` or subtype06 implementation. |
| Markon LGN/HBT/NRM | Separate ASCII parser; coordinate/range checks; NRM checksum unverified. Disabled by default. | Real golden NRM/history/alert fixtures, exact field counts and vendor checksum evidence. LGN/HBT have no checksum in current parsing; do not describe all Markon traffic as verified. EPB remains unsupported. |

Preserve null versus zero, raw categorical battery levels, receive time versus device time, GPS validity and historical flags. Do not convert mileage to km without documented units. Invalid data may be retained as diagnostics but must not update valid latest position. HTTP retry deduplication uses stable event ID; timestamped device retransmissions use the existing fingerprint. Heartbeats without device time intentionally do not get blanket raw-hash deduplication, since identical bytes can be separate observations.

## Minimal implementation sequence

1. **Receive correctness and accounting:** fix R1; add permanent regressions for EOF/reset/chunks/coalescing, terminal malformed input, login/profile identity and shutdown. Preserve spool-before-ACK and current security policy. Acceptance: complete final frames are processed once; incomplete data is explicitly rejected; no ACK before durable Put succeeds.
2. **One wire harness:** keep reusable protocol fixtures in `tests/fixtures/protocol/`, the Go TCP simulator/checker in `services/gateway/internal/harness/` only if shared by multiple tests, and orchestration under `utils/scripts/`. Prefer extending current tests and smoke orchestration; no separate harness service or second app Compose file. Generate private reports into ignored `.tmp/`, not committed packet dumps. Register isolated test devices through the normal authenticated API, use real TCP listeners, then verify PostGIS, REST and browser behavior. Test data must not affect real vehicles.
3. **Recovery and capacity:** inject failures around file write/sync/rename/directory-sync, ACK write, HTTP commit/response and spool deletion. Prove restart/retry accounting; add quarantine inspection/replay and queue-pressure visibility. Optimize queue indexing before considering a storage-engine replacement. Add bounded forwarding concurrency only after a measured need and ordering tests.
4. **Outbox and UI:** fix lease/housekeeping bounds, test downtime/retries/reconnect and browser access controls. Notifications can duplicate or be coalesced; committed log history must remain queryable. Browser tests must inspect actual rendered fields and filters, not only string helpers.
5. **Stress and hardware gate:** run the matrix below on a disposable environment, record the hardware and achieved capacity, then capture actual tracker login/location/heartbeat/alarm behavior. Hardware ACK timing and retry behavior remain mandatory evidence. Promote only the supported envelope.

Each phase is a small reviewable change with its own acceptance results. No production fault injection, application-data deletion, host bootstrap additions or architectural rewrite is part of this plan.

## Harness and stress matrix

Rates below are proposed test workloads, not support claims. Use configurable deterministic seeds and bounded timeouts; record host resources, image/commit IDs, packet corpus version, database settings and filesystem. Run with current trace-level file logging enabled so logging costs are included.

| Run | Workload/fault | Required result |
| --- | --- | --- |
| Golden and stream | Every supported fixture; every split boundary; one-byte chunks; multiple frames/read; mixed short/extended frames; invalid prefix/length/stop/CRC; partial EOF and data+error. | Expected fields and exact ACK/no-ACK behavior. Parser always progresses or requests bounded more data; no panic or infinite loop. Invalid input never becomes accepted GPS. |
| Baseline | 1, 10 and 100 devices at 1 frame/s each, 5 minutes per level; login/HBT/location/status/alarm mix. | No unexplained missing frames, stable resource use; latency and throughput recorded per level. |
| Capacity and burst | Ramp 128 then 256 connections; attempt 300; history uploads at 10 frames/s/device for 60 seconds, then idle/recover. | Explicit over-capacity outcomes, no uncontrolled goroutine/memory growth. Report first saturation point; do not require unsupported rates to pass. |
| Backlog | Queue depths 0/1,000/10,000; backend unavailable for 2 minutes, then recover while normal traffic continues. | Every durably admitted event reconciles; backlog drains at a measured net rate. Admission latency measured against depth; no cross-device starvation hidden by aggregate counts. |
| Crash points | Kill disposable gateway before/after each durability/ACK boundary; backend commit followed by lost HTTP response; kill/restart backend, database and realtime. | ACKed frames survive process restart; retries have no duplicate business effects; unACKed retransmissions are classified; stable event IDs survive. No claim of host-disk-loss survival. |
| Storage failures | Inject ENOSPC, permission errors, write/sync/rename errors and corrupt/truncated spool records in disposable storage. | No false ACK or persisted response; readable records preserved; corrupt files visibly quarantined; no silently skipped record or endless hot retry. |
| Identity and ordering | Unknown/disabled device, wrong profile, concurrent login, disconnect/reconnect, serial wrap, duplicate and delayed history, reassignment while backlog drains, clock changes. | No cross-tenant mapping, no latest-state rewind, no accidental deduplication of separate heartbeat observations. Policy rejection remains accounted for. |
| Outbox and browser | Lost response, lease expiry with two workers, slow realtime, many browser sessions, revoked session, browser offline/pause/pagination/filter/reconnect. | Commit precedes notification; bounded work and eventual REST recovery; authorized rows only. Browser table is bounded, not a guarantee that every row appears live. |
| Soak | Highest passing rate for 2 hours initially; 24 hours before longer-lived deployment claims. | No rising unexplained backlog, memory/goroutine leak, retention stall or unaccounted logging pressure. All admitted records reconcile after final drain. |

Record p50/p95/p99/max for durable admission/ACK, DB commit and outbox age; accepted/rejected connections; frame/CRC/unsupported counts; spool active/quarantine bytes and oldest age; HTTP retries; DB duplicates/points/logs; CPU/RSS/goroutines; log drops/file failures. Do not assign a universal latency SLA without hardware timing evidence. ACK p99 and maximum must satisfy the confirmed device timeout with margin at the accepted rate.

The manifest must classify each sent frame as not admitted, durably admitted or explicitly rejected. After a quiescent reconciliation snapshot, admitted IDs must partition into committed, active spool or quarantine; a spool record whose event already committed is a retry overlap, not a second logical packet. At final healthy drain, active spool must be empty and all expected accepted frames must be committed or have an explicitly approved rejection/quarantine outcome. Compare identity sets and decoded values, not only counts. A send() success or TCP ACK is not evidence of application admission. Application ACKs must match protocol/serial and imply durable admission. For no-ACK types use admission records/test hooks plus stored identity, not fabricated ACKs.

## Verification performed for this review

- Read the current application changes and traced the key runtime modules and tests listed above. This is a targeted whole-flow review, not an exhaustive proof of every code path or every vendor packet.
- Ran all gateway Go packages three times in an isolated copy, together with a controlled data+EOF reproduction probe. All existing tests passed; the probe reproduced R1 in all three runs. Output: ignored `.tmp/flow-review/go-review.txt`. The probe demonstrates a defect; it is not a passing regression for correct behavior.
- Previous implementation checks on the same application code: 29 Node/application tests passed with real PostGIS and no skips; Go vet/race, TypeScript/ESLint/Prettier and 12 container smoke checks passed. Those are prior results, not a fresh stress run.
- Full stress/soak, crash-point injection, real TCP-to-PostGIS reconciliation and manual browser/hardware location/alarm validation have not yet been executed. They are required before claiming loss verification or a supported fleet capacity.

## Implementation follow-up (2026-11-11)

Implemented the confirmed receive-loop defect, terminal diagnostic admission, bounded session configuration/capacity counters, pre-login cancellation, fail-fast listener errors and scratch-image readiness probe. The gateway is separated into startup, session and forwarding files. The file queue now has one process owner, a startup-built index, per-device ordered claims, bounded forwarding workers, per-device retry delays and offline quarantine inspection/replay with durable rejection codes. ACK-after-sync and commit-before-removal remain unchanged.

Outbox claims now carry ownership tokens in new migration003, renew before use and cannot be completed by an older claimant. Retention runs independently. Realtime authorization work is bounded and shared only inside one event. Log-page refreshes filter device hints and invalidate superseded filter requests. Parser revision is stored explicitly; old records are not rewritten. A final review also fixed microsecond cursor rounding and added deterministic PostGIS pagination coverage plus complete REST enumeration to the wire harness.

The Docker harness is resource-capped, uses real TCP and isolated PostGIS/REST/Socket.IO, and reconciles database/spool event identities with explicit device-retransmission accounting. It tests backend pause and gateway kill/restart. CI runs its small complete profile and decoder fuzzing. See [GATEWAY_LOAD_RESULTS.md](GATEWAY_LOAD_RESULTS.md) for outcomes, overload behavior and unexecuted long-running/hardware gates. Those remaining gates are not represented as completed or as a universal zero-loss guarantee.
